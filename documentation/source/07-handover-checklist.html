How to use this checklist

This is the last document in the set and the one to work through in order. It lists what exists, what the owner must be able to access, how to verify the site yourself, what remains open, and how to hand the project to someone else later.

Every statement here describes the state on 31 October 2026. Where something could not be verified, this document says so instead of assuming it works. The other six documents explain the system; this one is the acceptance procedure and the record of what was and was not proven.

  • Tick the boxes in sections 4, 5 and 11 as you confirm each item. A printed copy with dates is a valid record.
  • Do not write secret values here. Record only where a value is stored and whether it was confirmed present.
  • If a step fails, turn to section 9 for the first check, then to document 05 for the matching runbook.
  • Sign in section 11 only when the acceptance test in section 6 has been run by the owner.
What "handover complete" means. The owner can reach every account without the developer, the acceptance test passes on the production domain, the database backup exists outside the live system, and every open item is either closed or explicitly accepted as a known limitation.

The deliverable is a working website plus the means to run it: a public domain, the code that builds it, a Worker and database in the owner's Cloudflare account, and documentation that explains each part. No paid service, shared account or developer-owned resource is required to keep it running.

  1. Home page. Open https://rishavprasad.in/ in a new private window. You should see the portrait, the headline and eight navigation links. The address bar shows a padlock and no mixed-content warning.
  2. Every public page. Click About, Education, Projects, Skills, Experience, Achievements, Resume and AirShare. Each opens at /about/, /education/, /projects/, /skills/, /experience/, /achievements/, /resume/ and /airshare/; the current page is marked in the menu.
  3. Resume. On /resume/, click View PDF, then Download PDF. The file opens in the browser's PDF viewer and downloads from the site itself.
  4. Theme. Click the sun/moon button in the header. Colours switch; reload the page and the chosen theme persists.
  5. Narrow screen. Narrow the window to roughly phone width, or use the browser's device toolbar. The menu collapses to a button; open it and confirm all eight links. No page scrolls sideways.
  6. Custom 404. Open https://rishavprasad.in/this-page-does-not-exist/. You should see “Error 404” and a Back to home link.

  8. Contact form. Open /contact/, fill name, email and message, complete the Turnstile check, and click Send message. The page shows “Message sent. Thank you — I will reply to your email address.” and the message appears under Admin → Messages.
  9. Admin sign-in. Open /admin/, enter the owner password and click Sign in. Nine tabs appear: Profile, Education, Skills, Experience, Projects, Achievements, Resume, Messages, Media. Requires External Configuration If the page says the dashboard is not configured, or “Something went wrong”, see section 7 before continuing.
  10. Edit and publish. In Admin → Profile, change one word, click Save changes (“Saved to D1. Publish to rebuild the public site.”), then click Publish. A new GitHub Actions run starts and finishes green; reload the public page and confirm the change. Change it back afterwards.
  11. AirShare on two phones. Connect two phones to the same Wi-Fi and open https://rishavprasad.in/airshare/app/. On phone A click Create a room and note the 8-digit PIN.   12. Crawler files. Open /sitemap.xml and confirm the eleven public URLs; open /robots.txt and confirm it disallows /admin and /api/.
Pass condition. Steps 1–10 and 12 must pass. Step 11 passes when the transfer completes on two real phones; if it does not, record the Wi-Fi network type and treat section 7, item A4, as open. Admin step 9 may require the hash action first.

Transferring to a new maintainer

If someone else takes over, every asset can be moved because none is tied to the developer's account. Do the steps in this order so access never depends on a single person at once.

What moves, and how

AssetTransfer method
RepositoryAdd a maintainer, or transfer ownership from GitHub settings.
Worker and D1Stay in the Cloudflare account; invite the new maintainer as a member.
DomainStays at the registrar until a deliberate transfer with an authorisation code.
SecretsRe-issued to the new holder; never copied in a message or document.
Backups and documentationCopied out of band and kept in the repository.
Reply addressUpdated in lib/site.ts and deployed before access changes hands.
  1. Invite the new maintainer to the GitHub repository with write access, and to the Cloudflare account with the minimum role needed. Keep the owner on both until the last step.
  2. Hand over this documentation set and confirm the new maintainer can open all seven PDFs and the repository's markdown references.
  3. Transfer the repository (Settings → General → Transfer ownership) if ownership should move. Actions secrets travel with it; verify them afterwards.
  4. Re-issue secrets the new maintainer will hold: ADMIN_PASSWORD_HASH (new password), SESSION_SECRET, GITHUB_TOKEN, CLOUDFLARE_API_TOKEN. Changing a secret invalidates nothing publicly except the current admin sessions and pending publishes.
  5. Update the email reply address in the contact flow if it belongs to the outgoing owner, and confirm the new address in lib/site.ts before deploying.
  6. Hand over the private backup out of band, and confirm the new maintainer can read the sanitized export in the repository.
  7. Run the acceptance test (section 6) together on the production domain.
  8. Remove the outgoing person's access from GitHub, Cloudflare and the registrar only after the acceptance test passes, then rotate the two API tokens once more.
Domain transfer is separate. Moving the registrar requires an authorisation code and, for some extensions, a lock period. Plan it independently of the code handover, and do not change nameservers during the move.
